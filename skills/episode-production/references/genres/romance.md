# 恋综创作与改编

让观众从人物当下的回应和行动看懂关系变化，愿意继续看他们下一次怎么选。真实感不等于没有设计；设计相处情境、信息差和选择代价，让人物在情境里说话。

## 先确定这一轮改哪一层

- 从已有上下文确认素材、人物关系、时间限制、已接受的画面方案和允许改写的范围；只问确实缺失且影响结果的信息。
- 改编时先分清必须保留的事实、可改表达和可调整顺序。原作台词若受保护，不在视频提示词里偷偷改写；返回剧本层提出替换。
- “台词有AI味”优先处理接话逻辑、人物差异和信息表达；不能拿换音色、加气声或调语速代替写作修改。若用户已指明层次，不重复追问。
- 创作建议、已经采用的修改、实拍或生成验证分别标明。技能调用不自动授权付费生成、发布、发送消息或重做已接受版本。

## 关系推进先于台词润色

对当前场景用几句话明确：谁想靠近谁，谁还不知道什么，什么日常事情让他们必须回应，结束时关系或判断改变了什么。

优先把职业、习惯、喜好变成交流的入口和后续回收的细节。例如先记住对方不喝冰的，后来拿饮料时再体现；不能第一次见面就靠旁白宣布他很体贴。对方是否注意、接受或拒绝也属于事件。

没有关系变化的重复介绍可以压缩；保留能改变下一步选择的生活细节。不要机械给每个人相同时长，也不要为加快节奏把所有相处剪掉。悬念可以是一次没接住的邀请，不必凭空加前任、争吵或恶意嘉宾。

多人戏需要关注链：谁发起动作 → 谁首先回应 → 谁看见 → 谁因此改变接下来的行动。旁观者不必每句话都切一个表情，也不必被写成工具人。

## 把“AI台词”改成当下能说出口的话

逐段看接话，不孤立美化每一句：

1. 这句回应了上一句话、一个眼前动作，还是在替编剧概括主题？没有触发的观点输出，移到合适的采访或删去。
2. 说话人此刻具体想得到什么回应？用询问、试探、解释、转开话题或提出小邀请实现，避免直接说出全部心理分析。
3. 信息是否已经由道具、动作或上一句交代？删除重复解释，把空间留给对方反应。
4. 能否换任何角色来说而不变？按人物表达习惯调整直率程度、句长、幽默方式与回避方式，而不是给所有人同一套机灵话。

保留必要的姓名、时间、邀约条件和人物边界。自然不是删光信息、塞满“嗯啊”、故意语病或让人人结巴。偶尔完整表达观点、开玩笑、直球表白都可以；问题在于是否符合关系阶段和当下动机。

区分现场对白、事后采访、节目规则和字幕文案。现场不必解释观众所需全部背景；采访也不能提前解释尚未发生的选择，让悬念失效。

改写时附一行说明保留了什么剧情功能。已有自然的句子直接保留，不为交差全盘重写。具体示例见 [对白与场景交付](romance/dialogue-and-scenes.md)。

## 画面交代关系，也交代真实空间

- 先明确房间中的固定位置、座位归属、在场人物及行李/卡片等关键道具状态。使用世界位置或已定义座位名；画面左、右随机位变化，不能当作固定位置。
- 入场、询问、允许、落座、移动道具必须顺序可见。说“我能坐吗”时人已坐下，不靠加一句连续性口号修复。
- 用双人或多人中景建立谁在和谁交流，再选择值得看的反应。说话声可以继续而镜头看听者；避免逐句切单人正脸的机械轮流。
- 动作写到可判断的结果：“卡片平放并松手”比“她暗自退出竞争”可拍。非语言动作明确静默，不能变成模型追加一句自我解释。
- 背景人物仍在自己的位置，可以听、整理物品或自然安静；不要求每人每秒都在画内。只有覆盖到其应在区域却缺人，才判断连续性异常。
- 参考图决定可见外观，布局图/Blender白模帮助约束空间，但不能替代跨镜头状态。先贴合已有参考房间，未知尺寸标明近似；首帧不保证后面不会换座。
- 镜头内动作量需适合时长和模型能力。优先保留完整交流段落；不把一句话拆成一次生成，也不强塞过多人物动作进一个短片段。

## 按“动作带来的变化”剪辑

剪点由新的信息、视线转移、动作完成或回应触发。多切镜头不是节奏更好；关键迟疑需要时间，重复解释可以删。保证观众能看清动作的发起、接收和结果。

反应镜头必须属于该事件的时间与人物，不能用无关表情制造嫉妒。已有有效反应就保留；不要误报缺失后再补拍。特写揭示细节，双人景确认关系，较宽景恢复空间，各自有用途即可，不套固定比例。

字幕负责清楚传达，花字可轻点气氛，不能替人物宣布心动、替观众下结论或反复解释刚看到的动作。音乐不能遮住重要回答；是否需要留白由事件决定，不机械规定每隔几秒转折。

## 互动是剧情中的下一步行动

选项来自已经铺垫的真实动机，每项都能拍出不同后续。区分“去谈谈”和“复合”等不同承诺，不把见面当作接受恋爱关系。保留素材设定允许的拒绝或暂缓空间，不强迫配对。

在剧本中标出触发节点、问题、选项及各自下一场的变化；若只制作一集，不假装分支成片已经存在。投票揭晓前，结尾动作和旁白不能提前替主角选好。时长、片尾展示方式按项目要求，不将某项目的3秒规则普遍化。

## 交付与看片判断

根据任务只交付需要的层：场景改写、对白差异、分镜/剪辑说明或完整剧集。交给生成流程时，至少让执行者知道人物与状态、事件顺序、逐字对白及说话人、静默动作、机位与反应、出镜结束状态、字幕和互动节点；沿用项目已有格式。

看片先指出真正影响理解或沉浸的具体时刻，再提出对应修改。ASR识别完整不能证明台词自然；VAD漏字也不能直接证明没说。画面抽样不能证明整段无瑕疵；静帧不能证明声音和停顿自然。区分剧本问题、执行失败与剪辑问题，修在对应层。

研究外部节目时，明确完整视听、抽帧、转录、制作访谈、页面简介的证据边界；不从播放量推断制作流程，不把不同账号混为一组团队。来源与本项目案例见 [参考与观察记录](romance/observed-craft.md)。学习组织方法，写原创场景，不抄节目整段台词。
