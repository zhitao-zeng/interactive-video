# 互动短剧统一主线

用户已确认“一套系统，探险、恋综、悬疑作为三个项目”，并要求实际合并。

## 目标与范围

以现有 interactive-video 仓库 main 为唯一维护主线，统一创作、制作、审片、修复和交付入口。吸收三个内容分支及当前未提交的通用实现，同时保留各自已批准的素材、题材规则和生产配置。小说是独立仓库，本轮不合并其仓库或搬动其数据。

原内容工作区保持原样，使用临时索引提交授权合并所需的输入快照；不代为修改其索引或提交分支，不覆盖其他会话。开发改用从 main 创建的短期工作区，题材不再需要独立维护整份程序。

## 主线组成

- `scripts/creative_agent.py`：复用探险线已有的单作者创作入口，按 project 选择题材资料。创作阶段不调用媒体生成或生产采用。
- `scripts/interactive_video.py`：保留 import/prepare/assets/run/status，三个项目共用实现。项目生产与服务选择集中在 `configs/interactive.json` 的项目覆盖项中；每集 profile 的分辨率和并发仍优先。
- `application/agents/episode/codex_session.py`：合并恋综制作和探险创作的 Codex 登录适配，保持同一会话续接、实际附件、预算及宿主工具边界；不复制两套实现。
- 素材、分镜、声音、独立审片和有界修复保留悬疑主线能力，同时吸收探险/恋综的真实修复与恢复改进。
- `projects/{adventure,romance,suspense}` 保存各自小型源文件；生成媒体不入 Git。

## 运行数据

旧 inputs、outputs、delivery 和参考图片不移动、不复制大文件。统一入口通过本机路径链接使用已有资料。历史输出目录进入 runner 前解析到原实际目录，保留源位置、会话、take、审片与次数；读取状态不会生成或修复。

新任务由 main 代码执行。不同项目和每集的工作区、记忆、配置选择、审片和额度仍分别保存。已启动任务不热换代码，不重置预算；本次不运行图片、视频、TTS 或作者模型。

## 验收

1. 合并后所有现有测试通过，独立最终代码审阅的重要发现已修复。
2. 三项目创作 prepare 均装入共同能力及正确题材指导，不调用模型。
3. 项目配置保持各自设置，分辨率/并发优先级不丢失。
4. 从统一入口只读查询三条实际历史任务，目录及计数不改变，跨项目的版本不能误选。
5. 旧工作区改动保持，原始素材和媒体留在原位置；主线、文档及本机入口完成切换，未推送、部署或生成媒体。
