# 自动生产主线整合与三集无人干预验证

用户已批准：先整合主线，接通自动恢复，再跑三集无人干预验证；遇到卡点修通用流程，不靠操作员接续单集。

## 目标

从原始素材包通过统一正式入口，完成创作、素材准备、视频、审片、配乐、混音、导出和发布。宿主负责阶段、资源、预算、回执和恢复；创作与内容判断由既有生产 Agent 完成。

这次验收同时记录工程闭环与内容结果。完整 candidate 不能被计为 accepted；仅产生文件或进程退出零码不证明内容合格。无法在原预算内解决的任务必须说明真实原因，其他集继续。

## 复用与边界

- 复用 `interactive.film.run`、`interactive.production.run_episode`、episode host tools、既有 Conductor/回执/恢复接口；不新建队列数据库或另一套生产格式。
- 旧二十集、素材、视频、take、source、授权与计数不变。
- 保留 main 现有资源策略和其他会话 WIP；不代为提交或覆盖。整合先在 `codex/autonomous-production-20261023`，之后只把本任务增量接回 main。
- 运行任务代码冻结，不热换 worker。无远端源码 push；ModelScope 验证发布使用独立验证位置，不覆盖原二十集数据集。
- 新批次采用现有项目默认预算，并在启动前把实际值固定到批次记录；重启、切模型、换目录均不续额度。
- 首拍、审修、上传的当前状态由宿主决定。历史对话中的阶段性限制不能覆盖当前合法动作，永久用户约束和预算继续有效。
- 未变输入复用已有有效产物。提交不确定时保留原任务；允许的跨模型新 take 使用新目录并占原额度，不能把旧不确定请求改成已失败或覆盖后重发。
- 技术协议失败、内容问题、图像偏差、审核误报和服务不可用分别恢复。没有新依据的相同失败不无限重跑。
- 当前有效形态优先于已被替代的基础描述；纯文字源审不能声称看过未附的图片。真正图片检查仍使用实际参考图。
- 生图请求不得把明确动物/群体描述和强制单人、人类手部、无持物模板同时拼入。保留源设计的数量、物种、服装和明确持物。
- 编码、音乐和发布的已完成结果及时保存；后续阶段失败不丢前一步产物。

## 本次真实失败必须覆盖

1. 首拍完成后旧对话仍禁止 review/finish。
2. 图片供应超时但远端任务已经成功；应取回原结果，不另画。
3. 图片审查失败被误当源稿失败；正确源与文字次数应保留。
4. 场景物体被放进 in_frame，直到付费生图后才 KeyError。
5. 生图模板把动物群体写成单人角色。
6. 正确源稿的英文代词归属错；只修派生请求，保留 source。
7. Fast 实际 take 被未使用的 H3 文本校验阻塞。
8. 云任务提交不确定，换模型后必须保留原目录，且 max-attempts 是本轮次数。
9. 全稿审核区段 ID 拼接、选曲 JSON 残尾、错误 cue/实际源片段长度不足。
10. 明确音乐 offset 跨剪切点、postmix 顶层计划更新和原 native 计划保护。
11. 目的地错绑、恢复后空 delivery receipt、上传索引暂时不一致或进程退出。

## 实施阶段

### A. 统一可复现的代码

建立来源清单，逐项合并本次已测修复，保留主线新资源策略；不能把旧生产树的整个文件覆盖到 main。相同修复去重，冲突以当前主线接口为准。已有修复测试先在未集成基线上暴露缺口，再合并并验证。

### B. 接通恢复和交接

正式入口选择实际媒体通道，并持续处理已有返回状态。调度器自动推进确定性的下一步；需要创作的部分把具体集、镜头、字段与合法操作交给 Agent。格式坏不能伪造成正确内容；修复后仍走正常检查。

阶段完成记录和恢复动作共用同一份状态。普通恢复不调用操作员专用脚本、不改计数、不手写 passed。未知软件错误隔离任务，形成可复现证据，在通用代码修复后通过正式入口恢复。

### C. 发布与验证

将已使用的 ModelScope 同步逻辑参数化为正式发布出口，保留逐文件成功回执和单写者锁。只发布当前输入对应的完整导出；上传失败自动对账并续传。验收模式下正式成功要求现有视觉与声音门都通过；candidate 单独报告，不冒充成功。

## 三集验证输入

使用原始 1022 素材包中的 W10《失物海》、W12《瓶中四季》、W06《山海夜径》。分别覆盖常规人物/场景、人物与物件归属及配乐、非人和群体。保留原任务 brief、对白、事件顺序和片尾选择，不使用本轮人工修过的剧本或生成视频作为初始输入。

原任务文件在 `zhiyao-batch-20261022/.runtime/zhiyao-batch/task-<ID>.json`；它们绑定原 mini zip 和系列 material。验证新建 edition/run，原包和提供的参考可只读复用。先查三份原包内容与路径，再固定独立任务与预算。

媒体策略由当前正式配置和已验证通道决定，困难形态可使用正式首帧入口；每轮启动前固定策略。不能在看到结果后临时改某集参数却继续称无人干预。

## 验收定义

- 离线：本次真实失败能够经正常接口恢复；原产物与计数不丢，不重复付费提交，不误放真实内容失败。
- 真实：同一冻结代码版本、统一正式入口，三集各自独立 run。只观察，不中途写输入、改输出、换阶段、改预算或运行内部补救命令。
- 故障复现后修代码：失败记录保留；新版本按正式恢复路径复验。恢复验证与从原包首跑验证分开计，不冒称失败轮无介入成功。
- 报告三个独立结果：自动编排是否闭环、影片质量是否通过、发布是否完成；不能用其中一项替代其他项。
- 若确需人工接管，本轮无人干预失败；把原因修进通用入口后再验证，不靠样本专用补丁。
- 不保证模型能解决任意素材。预算内无法达到内容标准时准确停止单集，不改剧情核心或降低质量门来凑三集通过。
