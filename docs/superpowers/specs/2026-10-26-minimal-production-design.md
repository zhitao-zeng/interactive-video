# Clean Studio：最小无人值守视频生产项目设计

## 目标与成功定义

从 W10《失物海》原始素材包和原始参考图开始，用一个冻结版本完成创作、独立源审、首帧、视频、合成、正式视觉/声音终审和私有上传。

最终成功必须同时满足：

- 有效视频镜头 N/N；
- 当前完整导出的正式视觉与完整声音审核均为 accepted；
- 正式 accepted 成片 1 个；
- 私有数据集中可核实的上传 1 个；
- 全过程没有软件修复、人工接续、热换模型或代码。

候选片、进程 exit 0、单镜通过、ASR 正确、上传意图或小样成功都不算整集成功。发生软件修复、人工接续或冷恢复的轮次只记为恢复验证。

## 为什么新建项目

旧系统的问题不仅是单个函数错误，还包括重复事实、多个路由、历史恢复协议和多层兼容。继续修复有价值，但组合验证成本较高。新项目只保留当前目标所需能力，以历史失败作为回归证据，不继承旧运行状态。

新建项目不保证内容或模型问题消失。它只减少工程自由度，让剩余失败能明确归因于创作、审核、编译、外部服务或媒体能力。

## 方案选择与边界

采用“独立最小项目 + 冻结适配器”。不采用旧代码上的另一个生产入口，也不复制旧仓库后整体删除功能。

新项目根目录：

`/mnt/disk1/zengzhitao/interactive-video-studio-clean`

当前 `autonomous-production-v4-20261023` worktree 已交给另一位 agent。本项目不读取其运行状态、不迁移未提交修改、不在运行时导入其代码，也不修改其文件。

第一版只支持：

- W10 原始包改编；
- H3 首帧模式；
- 竖屏 1080×1920、25 fps、H.264/AAC MP4；
- JPEG 封面与片尾；
- ModelScope 私有数据集发布。

第一版明确不支持：SD/无首帧通道、旧 edition 恢复、旧会话迁移、多生产模式、通用长期记忆、插件式恢复框架和并行多集调度。

## 可复用基础设施

允许冻结复用已有稳定能力：

- Codex/LLM 调用适配器和正式密钥加载方式；
- 图像生成、H3、ASR、FFmpeg 和 ModelScope 的服务适配器；
- 独立视觉、完整声音审核所需的提示词、媒体读取和判定协议；
- 原包结构解析、源说话人证据和 source-to-shot 对照经验；
- 历史失败样例及回归数据。

复用规则：

1. 所需代码或提示词复制到本项目并记录来源路径、哈希和日期；运行中不得引用会变化的 worktree。
2. 不复制旧 episode 状态机、恢复路由、输入计数或旧稿件。
3. 密钥只从既有私密环境加载，不写入源码、配置示例、日志或 manifest。
4. 媒体生成和挂载模型不进入 Git。
5. 复用适配器也必须经过本项目的真实调用验证，不能凭旧项目成功直接视为可用。

## 最小架构

项目只保留以下职责单元：

- `domain`：Episode、Shot、Reference、Review、Operation 等不可变输入与状态合同。
- `store`：唯一事务状态库、尝试计数、外部 task ID 和不可变回执索引。
- `agents`：创作者、独立审核和异常修复 Agent 的有限会话接口。
- `compiler`：把已验收镜头编译为首帧、H3 和参考附件请求。
- `pipeline`：唯一宿主状态机，推进正常阶段并分流异常。
- `providers`：冻结的模型、媒体和上传适配器。
- `cli`：唯一 `produce` 入口和只读 `status` 入口。

不新建队列数据库、微服务、通用规则引擎或世界状态引擎。状态存储使用 Python 标准库 SQLite；媒体文件和原始回执保留为不可变产物，数据库只保存其身份、哈希和当前投影。

## 一份镜头事实源

作者只维护需要创作判断的字段：

```json
{
  "shot_id": "shot_001",
  "scene_id": "S1002",
  "source_segments": ["seg_3"],
  "location": "registered-location-id",
  "start_state": "镜头零点的实际人物、物件和灯光状态",
  "action": "镜内发生的动作与明确时序",
  "end_state": "镜尾实际人物、物件和灯光状态",
  "camera": "机位、运动和构图意图",
  "shot_scale": "明确景别",
  "visible_characters": ["registered-subject-id"],
  "dialogue": [{"speaker": "registered-subject-id", "line": "原包逐字对白"}],
  "reference_subjects": ["registered-subject-id"],
  "duration_seconds": 12.0
}
```

Episode 级事实单独保存：标题、180–300 秒目标时长、画风 ID、原包固定的片尾问题与选项，以及音乐 cue 时间线。片尾问题和选项逐字来自原包，宿主生成 3 秒片尾卡；不得由作者或后期另行改写。音乐 cue 包含起止时间、情绪和声景意图，宿主据此检索候选并保存实际音频证据；需要内容判断的曲目采用由异常 Agent 完成，宿主不得伪造 accepted 试听结论。

规则：

- 作者不另写 `opening_frame`、`visual_prompt`、`motion_prompt` 或独立 storyboard 状态。它们全部由宿主编译。
- `start_state` 是 t=0，`action` 是镜内过程，`end_state` 是镜尾。正常的镜内开灯、加入卡片和离开不属于开场矛盾。
- `end_state` 必须是实际状态，不能只写“对白完成、准备下一镜”。
- 相邻镜审核比较实际写出的关键状态，允许跳切、反打和省略过渡，不维护隐藏世界状态。
- 作者可以用代码生成 JSON，但最终输出必须逐镜通过场景对应、字段证据和相邻状态审核；不迁移或修补 A5 的作者脚本。
- 原包 `flow.speaker/line` 是对白归属和文字的证据，必须逐句保留，不能靠模型猜说话人。

宿主编绎：

- opening 由 location、start_state、camera、shot_scale、visible_characters 和参考清单派生；
- motion/H3 由 action、end_state、dialogue、持续时间和当前 opening 派生；
- visual/motion/H3 的请求指纹绑定源镜头、编译器版本和参考清单；
- 内容修订只重编译受影响镜头及明确依赖项，保留无关镜头、已通过素材和原计数。

## 一份不可变参考清单

创作前，从原系列素材和冻结风格包生成唯一参考清单。每项包含：

```json
{
  "subject_id": "registered-subject-id",
  "path": "immutable-relative-path",
  "sha256": "64-hex",
  "role": "identity|wardrobe|location|style",
  "scope": "允许约束的视觉范围",
  "order": 1
}
```

作者只选择注册 `subject_id`，不填写图片文件名或猜生产注册名。宿主按“身份 → 衣装 → 地点 → 风格”的冻结顺序展开附件；风格参考只约束色光、材质和渲染，不复制人物、衣装、剧情、文字、布局或 POV。

实际生成请求、图审、视频请求、缓存和哈希都使用同一份展开结果。未注册、未绑定、缺文件或哈希变化必须在付费前给出具体原因；作者引用错误才交 Agent，宿主注册/编译错误由宿主修复。

## Agent 职责

### 创作 Agent

- 从原包和原始参考说明独立创作完整镜头稿。
- 收到带字段、原句、时间和来源证据的审核意见后，在同一作者会话和原额度内修订。
- 不生产首帧提示词、H3 请求、恢复计划或上传指令。

### 独立审核

- 只判断，不改稿。
- 结构错误由代码检查；语义冲突由审核模型判断。
- findings 必须包含实际字段路径、逐字原句、时间位置和证据来源；原文问题还必须有原始区段。
- 二次确认只用于撤销误报，不得反复审核同一稿件直到通过。
- 同一内容指纹只复用同一有效结论；内容变化才重审，服务失败不是有效 verdict。

### 异常修复 Agent

正常生产不启动生产 Agent。只有确认需要内容判断时才调用，输入为最小范围：问题镜头、必要相邻镜、原文、当前字段、审核证据、允许修改字段和余额。

修复通过一次 typed `check/apply` 接口完成。`apply ok=true` 只表示补丁被采用，宿主仍须重新编译和验收；Agent 说“修好”或工具调用 completed 不代表内容通过或整集完成。

## 唯一宿主状态机

正常阶段固定为：

```text
AUTHORING
→ SOURCE_REVIEW
→ COMPILING
→ FIRST_FRAMES
→ VIDEOS
→ MUSIC
→ ASSEMBLY
→ FINAL_REVIEW
→ PUBLISHING
→ COMPLETE
```

宿主根据当前持久状态和操作回执推进，不让 Agent 选择阶段或调用 finish。

- `accepted`：当前完整导出通过正式视觉与声音验收，但可能尚未上传。
- `complete`：accepted 导出已完成可核实上传。
- `blocked`：保留当前阶段、真实原因、合法下一步和原余额；不能被已有 assembly 覆盖成 accepted。
- `candidate`：完整但未正式 accepted 的媒体结果，不上传。

每个阶段只消费本阶段所需证据。首帧合格不代表视频合格，ASR 正确不代表声音自然，单镜通过不代表整片通过。

## 状态、计次与恢复

SQLite 保存三类事实：

1. episode 当前阶段、冻结配置和状态；
2. 每镜源内容哈希、编译哈希、图片/视频/input 计数；
3. 操作 idempotency key、外部 task ID、输入哈希和回执位置。

标准额度在启动前冻结：每镜最多 3 个图片候选、3 个视频 takes、2 次 input revisions，单集最多 3 次启动；创作 Agent 单次最多 1200 秒、累计最多 5400 秒。不得通过重建 edition、清零计数或换目录追加。

- 网络临时故障只按既有安全策略有界重试，不调用内容 Agent。
- 已提交任务先查询、下载和对账；查询不算新生成，重新提交必须占用生成额度。
- 提交不确定时禁止盲目重新 POST。
- 凭据失效、配额耗尽、未知宿主异常和无内容进展明确停止。
- 审核服务错误不等于内容不合格。
- 冷恢复保留同一 edition 和计数，但该轮只能标记为恢复验证。

## 验证顺序

### 1. 历史失败回归

将旧 v2、A3–A5 的只读失败形状做成通用测试，至少覆盖：镜头—场景错贴、起始/镜内/结束时间、首帧内部矛盾、相邻镜重复动作、派生字段同步、未注册引用、部分首帧恢复、提交不确定、技术故障、旧审核失效和 candidate 不上传。

测试不修改旧目录，不为具体 clip 写生产特例。

### 2. 真实作者与审核闭环

从原包进行真实创作和独立审核，确认真实冲突能被定位、误报可撤销、原作者能修订。不能用 mock 审核证明模型判断准确。原作者在标准额度内无法交付一致制作稿时停止，不进入付费媒体。

### 3. 小规模完整媒体链

用已通过的制作稿完成代表范围的参考展开、首帧图审、视频、解码、ASR、合成、正式视觉/完整声音审核和私有上传。保存实际 prompt、附件、task ID、计数和全部回执。代表范围的通过不计作整集通过。

### 4. 新冻结 W10

以上全部通过后，创建独立 edition，冻结配置，只运行一个 `produce` 并等待最终结果。运行中不逐镜人工改稿、改提示词、改时长或追加定点重拍，保留系统自己的自动检查与有界重试。

若出现新的通用软件问题，保存证据、停止并最小修复；该轮后续只能算恢复验证。需要从头成功时，必须在修复和分层验证完成后另开冻结 edition，不能反复重建同一失败任务制造成功。

## 本项目刻意不做的事情

- 不兼容旧 edition 或旧恢复协议。
- 不同时支持多个视频通道。
- 不让生产 Agent 驾驶流程。
- 不让作者和编译器重复维护同一状态。
- 不用复杂世界状态、长期记忆、通用恢复框架替代明确的字段和回执。
- 不通过降低验收、增加额度或忽略历史失败来追求成功。

## 未决风险

- 新项目的审核协议仍需真实模型验证，不能预设比旧审核更准确。
- 新适配器可能在长 JSON、附件传递、ASR 或正式音画审核上暴露不同问题。
- 单镜和小规模成功不能证明 20 镜整集稳定。
- 媒体模型可能无法在标准额度内达到正式质量门；届时应如实停止，而不是继续增加系统复杂度。
