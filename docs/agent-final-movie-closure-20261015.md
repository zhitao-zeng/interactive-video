# Agent终审回修闭环（2026-10-15）

旧路径先完成原生镜头的有限修复，再审导出的成片。成片问题只写报告，未回到Agent；候选请求被一致性检查拒绝后也直接缓存阻塞。此次把两处结果接回已有反馈与修复循环，不增加拍摄额度。

成片检查抽取实际导出文件的画面，标注clip、原镜号和全局时间，提供批准源文、当前请求与完整字幕cue。完整审查才把问题映射到clip反馈；服务失败或缺证据只阻止验收，不能靠部分结论盲拍。原生verdict/take保留，成片证据独立保存并复制到Agent沙箱。

候选的请求内容、拒绝原因和图片观察返回原Agent；最多三份候选，拒绝本身不消耗视频次数。stop、输入改变、接口失败或额度用完结束该路。native keep不能清除实际成片问题；这种候选也返回拒绝反馈。

每轮导出和终审证据保留版本。输入未变时复用同一影片，验收后不重新编码。小说发布将已审候选受控复制到正式文件时，同步重定位审查身份。旧审查已启用而新媒体报告遗漏字段时，仍从集目录加载并核对，不能绕过门禁。

## 独立审片也进入回修（2026-10-15）

前述7类视觉问题原本只在运行结束后出报告，未进入Agent；不是因为审查“过严”而被有意豁免。本次增加同一成片的独立审片接入：注册前核对实际影片、全局时间、每条问题的坏镜头与截图；正确对照镜头仅保留作证据。

独立结果与Qwen结果共同形成原有final_cut反馈，沿现有managed Agent、候选校验、拍摄额度和影片导出循环处理。注册后，每个新影片由同一sandbox服务的独立观察Agent读当前JPEG与批准源文，逐条说明旧问题仍在或已经解决；单纯Qwen通过或原生keep不能清除它。失败/缺图/服务错误阻止验收，不盲目拍摄。只有原始视频历史允许的次数能够生成，拒绝候选不计视频次数。

原始报告、每次沙箱session及观察结果保留；受控发布复制影片时同步独立审查身份。小说与互动线共用这一实现，小说既有request_scope、对白绑定及高层finish门禁保留。接入函数为review.independent.register，互动Agent入口提供independent_report参数；注册后的重审在现有final_cut调用内自动执行，不再依赖会话结束后的手动接力。
