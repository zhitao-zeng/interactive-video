# 统一主创 Agent

已批准稿进入实际制作时使用正式单集入口。已有片段的制作可通过
`scripts/episode_agent.py prepare/run --existing-production --novel-dir <已准备的制作目录>
--episode <集目录名> --input-mode script --output-root <独立Agent记录目录>` 接管。
该方式直接使用原制作目录中的计划、素材、任务回执、视频及修复预算；Agent会话和工具记录
另存，不能同时保留另一个宿主往同一集派发任务。`prepare`只交接、不生成；`run`由现有
控制器执行render/review/apply/finish。原默认隔离模式保留，不自动复制已有视频并重开预算。
接管模式遇到单回合限时会自动续接保存的同一会话，只使用已记录的剩余总操作时间；
不通过retry-issues重开时间窗口，批量调度或等待素材的挂起仍沿原调度规则处理。

这不把轻量文字比较稿直接当生产稿：选定稿仍需先完成结构化分镜和实际素材绑定。
创作入口本身的creation_only边界如下，不能把启动创作误称已经调用制作Agent。

一个持续会话负责从完整素材包或原创意图写到剧本、分镜、互动选择和空间设计。
本入口只创作，不调用普通source流程先买一份初稿，也不启动图像、视频、配音、
素材生成、生产采用或发布。当前版本在荒野独立分支中实施。

## 输入与执行

入口是`scripts/creative_agent.py`，使用现有episode Agent SDK和素材ZIP导入器。
任务JSON提供`mode`（adaptation或original）、`project`、完整`brief`、目标时长范围，
改编另提供`source_archive`。可指定世界卡、片尾卡时长和必须保留的互动目的地。
角色图和原始文本完整复制到独立输入，原ZIP另行保留。原创模式明确使用用户意图，
不伪造外部素材来源。不同任务版本使用不同输出目录，已有候选和会话保留。

```bash
PYTHONPATH=src .venv/bin/python scripts/creative_agent.py prepare \
  --task /path/to/task.json --output-dir /path/to/independent-run

PYTHONPATH=src .venv/bin/python scripts/creative_agent.py run \
  --task /path/to/task.json --output-dir /path/to/independent-run
```

`prepare`不调用模型。`run`直接进入作者会话，只提供创作所需文件操作；
不会启动生产工具服务。沿用已选沙箱配置的每次创作时限和总执行时限；本轮分别为
1200秒和5400秒，未增大配置。修订与续跑累计已用时间，不重置预算。
需要继续失败任务时使用`--resume`，保留实际会话和预算。`status`只读取当前状态。

完整稿经通读发现问题时，用`run --resume --feedback /path/to/review.md`交回同一个
作者修订。反馈另存、原始任务不变，每次调用前后的候选和验证结果保留；宿主不代写剧情。

默认使用现有配置；显式`--config`可选择任务级配置。本轮默认文字接口在产生任何
创作前返回402，随后复用了项目已存在的Codex登录态执行方式。该适配保存在
`interactive/creative_codex.py`，没有修改其他内容工作树或全局模型配置。
初始失败会话归档保留，真正的作者会话建立后持续续接，不能把不同SDK的UUID混用。

Codex创作容器使用已有运行方式和登录，不复制认证文件。它只有独立输入、输出与
Skill包，未挂载`tools/episode.py`或生产源码，不安装媒体宿主工具。原生文件/图像/
本地文件处理工具用于创作；旧SDK的Read/Write等名字在此表示这些操作。

## 实际接入的经验

只安装一个`episode-production`包，在manifest中列出本轮应读取的资料：

- 完整camera-language手册及H3表达边界，复用小说主工作区现有版本。
- authoring中的表演前置、事件触发的语气变化、闭嘴观察和音频条件选择。
- dialogue-craft中的现场动机、人物表达差异、删重复说明及保留事实的口语改写；与声音表演分开判断。
- spatial-blockout中的固定世界锚点、placed与in_frame、机位路径、空间假设及失败经验。
- 按项目选择旅行、恋综或悬疑创作指南，并保留对应参考资料。
- 从现有METHODS导出六种本地创作方法，作者选用必要方法，不启动六个作者。
- 原有repair-playbook和修复原则，用于脚本自审及后续交接；当前阶段没有重拍权限。

Skill主入口和输出合同识别`phase: creation_only`，将其交给专门创作合同。
输出仍使用chapter_script、说话人/turns、镜头编号和片段分组等已有交接概念，
H3英文请求、素材绑定和实际生产采用留待明确的制作阶段。

## 交付与验证

作者完成`output/episode.json`与创作笔记。宿主只验证来源引用、完整镜头覆盖、
时长和分组、保留的互动选项及空间计划引用，并从同一稿件格式化以下文件：

- 剧本.md与分镜.md，包含世界卡及片尾选择卡的计划位置。
- 互动选择.md与interaction.json，selected保持null。
- 白模空间设计.md与spatial_plan.json；本阶段只是设计，未运行Blender或生成图。
- chapter_script.json、clip_groups.json、episode.json与作者自审记录。

原始文档、图片、安装资料、每次调用前后候选、原生事件、实际读取路径、验证结果
和会话ID保留在独立工作区。脚本格式与来源定位通过不等于影片好看；本轮还需通读
整稿的推进、表演与连续性，并让用户审阅。原生图片附件证明提供了图片，不能替代
作者对身份/造型的实际判断，更不能冒充生成成片的验收。

## 本轮笑之国

真实输入是原附件《探险视频 第一集.zip》，包含55镜原稿和两张知遥角色图，
没有把已完成v3改稿作为作者输入。当前用户允许在事实与互动方向不变的前提下
重排和压缩表达，要求真人、9:16、3–5分钟、开场异常及第二镜世界卡，使用
已试听偏好的无参考音频表演方式。原包的旧逐字照读、时间码和证据后期贴字
要求由本轮明确创作要求替代，原文仍完整保留用于核对。

任务、模型通道选择、首次402、代码测试及实际作者调用记录位于
`.runtime/unified-creator-laughing-country-20261015`。视频/图像/TTS新增均应为0，
旧成片、素材、次数和原生产配置不变。本轮不提交、不推送、不跨分支同步。

资料/原始素材均有读取记录，三个实际输入文件与原ZIP内容一致。

宿主自动退回引用与分组错误，独立通读反馈再交回同作者，修正事实错置、核心含义遗漏、

未解决的重要发现；原文未知的发送者、制度幕后和居民结局仍未知。当前作品是可审阅的
