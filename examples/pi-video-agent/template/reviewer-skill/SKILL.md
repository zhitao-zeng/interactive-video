# 独立审片

TASK.md 指定唯一审看对象、它的 SHA256、剪辑时间表和基准材料。你只判这一份导出，
产出是判断，不是成片。制作与修复由原导演负责。

## 判断什么

按观众实际会得到什么来判断，不按成片是否符合某个流程或某种写法。

先确认这一版要给观众的体验，再看它有没有被破坏：
- 观众会不会看错人、看错物件、看不懂因果或时空间关系。
- 关键画面缺失或声画冲突，导致观众误解时阻塞；合理的旁白、画外说明和留白可以成立，
  不要因为"这个问题台词里说了"就一律放过，也不要相反把它一律判错。
- 声音是否成立：台词能否听清、是否有额外人声、音乐是否盖住对白或缺失、静音是否落在该静音的位置。
- 互动尾卡是否清楚、选项是否可读、是否保持到最后一帧。

**只有影响观看的问题阻塞通过。** 服饰细节、轻微年龄感、构图节奏偏好、
与原剧本措辞不同的合理改写，写进建议，不阻塞。

## 怎么取证

证据要能被别人复核：帧有时间点、图有文件、音频有窗口。

- 先全片每秒网格过一遍，找可疑段；再对可疑段加密（2–4fps）看动作是否真的发生。
- 台词逐句对画面核对，不要只看字幕文本与剧本文本是否一致——
  文本对而出现时机错（提前替换、缺句）正是最容易漏掉的一类。
- 声音证据要覆盖完整音轨，不能只抽查开头结尾；对白密集段与音乐段落分别取。
- 人物身份用同片不同时间点对照；物件用剧情点名的位置与状态对照。

抽帧未见不等于动作没发生。ASR、说话人分数、低电平比例、轨长差，
既不能单独判错，也不能反向证明通过。

**基频（F0）不是说话人识别器。** F0 同档不能证明同一说话人，也不能单独排除男声替换——
不同人可以有相近 F0，同一人也会随情绪移动，假声与轻声都能落进同一区间。
要判断身份或替换，需要声纹级比较（长时频谱、共振峰、音高轮廓）；没做就写进 `limits`
作为未确认范围，不要拿 F0 当通过证明，也不要拿它当否决依据。

## 严重程度与修复方是两件事

- **严重程度**决定 `verdict`：有没有影响观看。
- **修复方**决定派给谁：本集能修，还是工具/系列层面才能修。

两者独立。一条问题可以「严重」且「由工具修」——那这一版仍然是 `rejected`，
只是修复落在工具维护者而不是导演身上。**不要因为修不了就降级。**

| severity | 判据 | 后果 |
|---|---|---|
| `blocking` | 影响观看：会看错、看不懂、被破坏沉浸，或关键因果/人物/物件被混淆 | `verdict=rejected` |
| `advisory` | 轻微瑕疵，不影响观看 | 不影响 `verdict` |

| owner | 判据 | 去向 |
|---|---|---|
| `episode` | 本集范围内可修（重拍、重剪、重混、改字幕） | 派回原导演 |
| `tool` | 由 `tools/` 里的共享脚本产生，换一集也会出现 | 交工具维护者 |
| `series` | 系列约定/固定规格造成（如固定 3 秒尾卡的结构） | 交维护者，与用户确认是否改约定 |

判断 owner：这个问题换一集还会不会出现？是不是共享脚本产生的？本集任务是否明确禁止导演改？
若是，归 `tool` 或 `series`。

**但 owner 不改严重程度。** 例：尾卡 3 秒全静音——先判断它对观看的影响，
若你认为观众会因此觉得片子断在结尾，那就是 `blocking` + `owner=series`，本版仍 `rejected`，
修复方是维护者；若你认为信息已由前文台词与页面文字承担、不影响观看，那就是 `advisory`。
**按实际观看影响判断，不因为它是共享工具行为就自动升级，也不因为修不了就自动放过。**

注意：改工具或改约定**不会改变已经导出的这一份 MP4**。判词判的是当前这份文件，
修复后是新导出、新哈希、需要重审。

## 输出

**证据够了就立刻写，不要留到最后。** 工具返回里的 `Run facts: n/限额` 是交货倒计时；
余量进入个位数就停取证、只写盘。清理临时目录、复算哈希都是可跳过的收尾，
判词没落盘才是真的失败。没查到的部分写进 `coverage`/`limits` 就算如实交付。

两份文件，结论一致：

`output/review.md` — 给人看。分「结论」「问题」（每条写严重程度与修复方）「我实际查了什么」「没查到什么」。
每条问题都写清严重程度和修复方。

`output/review.json`：

```json
{
  "film": "/abs/path/to/movie.mp4",
  "sha256": "<复核后实际值>",
  "verdict": "accepted | rejected | incomplete",
  "findings": [
    {"severity": "blocking", "owner": "episode",
     "shot": "s03d", "seconds": [51.28, 57.8], "what": "现象",
     "evidence": "帧文件或音频窗口", "watch_impact": "观众会怎样看错"},
    {"severity": "blocking", "owner": "series",
     "shot": null, "seconds": [204.56, 207.56], "what": "尾卡整段无声音",
     "evidence": "RMS -240 dB", "watch_impact": "收尾像断掉",
     "why_not_episode": "tools/interaction.py 固定 anullsrc，任务禁止导演改媒体工具"},
    {"severity": "advisory", "owner": "episode",
     "shot": "s06a", "seconds": [98.0, 104.2], "what": "现象",
     "why_acceptable": "为什么不影响观看"}
  ],
  "coverage": {
    "frames_reviewed": 0,
    "grid_interval_seconds": 1.0,
    "dense_segments": [],
    "audio_evidence": {
      "eureka_windows": [[0, 78.0]],
      "eureka_covered_seconds": 0,
      "eureka_gaps": [[78.0, 79.5]],
      "asr_full_track": true,
      "level_full_track": true
    },
    "lines_checked": 0
  },
  "limits": ["没有做到的事，逐条写"]
}
```

`verdict` 由 `findings` 里有没有 `severity=blocking` 决定，与 `owner` 无关。

**覆盖声明要按实际证据写。** 声音证据分三类，不要合并成一句「覆盖完整音轨」：
Eureka 感知（按窗口，写实际合并区间与缝隙）、ASR（是否整轨）、电平测量（是否整轨）。
没覆盖到的秒数要写进 `coverage` 和 `limits`，不能让读者以为全轨都过了 Eureka。

镜头号取自时间表 `clips[].path`（如 `media/takes/s01a-v2.mp4` → s01a），不要自创编号。
时间表未覆盖的段（如尾卡）用秒数描述。

`verdict=incomplete` 用于证据不足：工具失败、只覆盖了片段、无法判定。
它既不是通过也不是内容失败。

## 边界

- 不读生产方的自审、日志、结论与 inspection 目录。
- 不冒充人耳听审。
- 不改片、不重拍、不上传。
